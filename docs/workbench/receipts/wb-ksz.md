- What the rows read: every row launches the REAL detached host child through the marked launch twin. The rows read only what crosses that process boundary: the child's inspect snapshot, the replies on the child's own socket, the names in /proc/<pid>/environ, and one marker file per provider call, written beside the workspace by the reviewed local provider fixture.
- H0 (instrument): the child is alive and is not the test process. The host holds an env canary whose name never reaches the child's environment. The canary value is plain, so the shared redaction would leave a leak of it visible, while the fake token used by H7 is masked.
- H1 (JS VM escape attempt): inside the child, every constructor-chain probe over the 14 injected callables, plus a bare Function(), is a realm EvalError (43 of 43). process, require, globalThis.process and Buffer are all undefined. No probe reaches the provider.
- H2 (crafted raw RPC): the parentPort vehicle probe is an EvalError. Forged authority fields are refused by the provider's input schema (validation). A forged principal option is refused in the VM. Nested workflow resolution is refused, and agent() resolves null on the deterministic backend. Only the granted control call reaches the provider (1 marker), and its answer is plain data in the VM realm.
- H3 (unknown grant): a capability outside the invocation's reviewed manifest, local or native, gets an authorization denial and makes no provider call. An expired grant does not apply here: detached grants are fixed at launch and never expire.
- H4 (observer-only stop): a child launched with the inspect permission alone refuses cancel, shutdown and execute with typed authorization denials. Its control audit stays empty, it keeps serving inspect, it stays alive, and it never runs its script.
- H5 (cross-workspace ref): two children run in separate workspaces. A frame naming the other workspace's invocation, sent on either child's own socket, gets "Invocation ACL mismatch." (authorization). An extra authority field, an unknown verb and two commands on one connection are each refused (validation). A crafted re-execute starts nothing. Neither provider gets a call from the other workspace.
- H6 (schema pollution): __proto__ and constructor keys, and input deeper than 64, are refused at the VM boundary before any host frame. The realm's prototype stays clean, and only the control call reaches the provider.
- H7 (secret env not displayed): the canary name is absent from both children's environments. A credential-shaped placeholder in a result, in a log row and in a failure message leaves the child as [REDACTED].
