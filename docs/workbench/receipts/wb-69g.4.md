# wb-69g.4: W16 gap: Claude interrupt control stays unregistered because SDK Query.interrupt() requires streaming input while the host queries with string prompts

## 2026-11-11 receipt: the string-prompt control channel measured against the installed SDK 0.3.300 (cut #1, trunk b1772ff4)

- Premise under test (the bead's 2026-10-15 filing): the SDK's doc comment on `Query` says its control requests "are only supported when streaming input/output is used", while `src/workbench/claude-host.ts` calls `query({ prompt, options })` with a string prompt.
- Trunk state at this cut (read, not changed): `src/workbench/control.ts` lists `interrupt` as the one native control action of `claude-agent-sdk` (`NATIVE_CONTROL_ACTIONS`), and `src/index.ts` keeps each live Claude query's seam from the host's `onQueryLive` hook for `workflow_control` (wb-cra, wb-hqa).
- Read in the installed `@anthropic-ai/claude-agent-sdk` 0.3.300 (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.mjs` at this cut): the CLI is spawned with `--output-format stream-json --verbose --input-format stream-json` whatever the prompt's form; a string prompt is written as one stream-json user message on that stdin after the initialize control request, and the query is a single-user-turn query whose stdin is ended when its run ends; `interrupt()` sends an `interrupt` control request on the same stdin. An AsyncIterable prompt is written by `streamInput`, which ends stdin right after its last message unless the query has bidirectional needs (SDK MCP servers, hooks, `canUseTool` and the other callbacks its `hasBidirectionalNeeds` lists).
