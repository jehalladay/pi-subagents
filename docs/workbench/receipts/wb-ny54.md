For each of those five values and each of the four limits, runWorkflow's promise rejects before a 0 ms timer set just before the call fires: R073-IMMEDIATE. `Number.MAX_SAFE_INTEGER` is accepted as each run limit and 2^53 is refused: R073-SAFE-INTEGER. Concurrency 1 completes and never runs two agents at once: R073-ONE. `workflowConcurrency()` gives 1, 1, 1, 16 and 16 for 0, 1, 2, 18 and 64, and a run with the concurrency unset completes: R073-DEFAULT; with the concurrency unset, a 20-agent fan-out holds exactly min(20, workflowConcurrency()) agents in flight: R073-DEFAULT-IN-FLIGHT. With the caps unset, a run fails at agent `WORKFLOW_AGENT_CAP` + 1 (1000 agents), at a `parallel()` of `WORKFLOW_ITEM_CAP` + 1 items (4096 items) and at nested `workflow()` call `WORKFLOW_NESTED_CAP` + 1 (256 calls), each refusal naming that default: R073-DEFAULT-CAPS. Before cut #1, a concurrency of 0, -1 or NaN parked every agent behind a semaphore with no permits, so the run hung, and 0.5 and Infinity were accepted (the cut #1 red below).
- EAT-R073, host limits. `HostAdmission` refuses each of 0, -1, 0.5, NaN and Infinity as each of its four limits with a `HostAdmissionError` of code `invalid-limit` whose message names the limit, and accepts 1: R073-LIMITS-sdk-queries, -child-processes, -forge-operations and -queue-deadline. A pool limit accepts 2^31 and `Number.MAX_SAFE_INTEGER`, and 2^53 is refused as each pool limit and as the queue deadline: R073-SAFE-INTEGER. The queue deadline accepts setTimeout's ceiling, 2147483647 ms, and one more is refused with a `HostAdmissionError`: R073-DEADLINE-CEILING. A budget built with limits 2, 3 and 1 and a 250 ms deadline reports them, with nothing in flight or queued: R073-SNAPSHOT. A snapshot carries, per pool, exactly `limit`, `inFlight`, `peakInFlight`, `queued`, `admitted`, `refused` and `cancelledWhileQueued`, each a number: R073-SNAPSHOT-COUNTS-ONLY.
- EAT-R074, the shared budget. A host builds one `HostAdmission` and hands it to every run it starts (`RunWorkflowOptions.hostAdmission`). It holds three pools with separately configured limits, in the order `sdk-queries`, `child-processes`, `forge-operations`. `dispatchPools` charges an agent dispatch to `sdk-queries` and `child-processes`, a node dispatch to `child-processes` (for the capability ids `forge.gate.status`, `hyperunix.find` and `forgery.gate.status`), and a `forge.gate.status` node to `forge-operations` as well; a `hyperunix.find` or `forgery.gate.status` node is not charged to it: R074-CHARGES. Three runs sharing a budget of 2 SDK queries hold 2 agents in flight with 7 queued, and never more than 2: R074-SDK. Agents and nodes of three runs share 3 host child slots: R074-PROCESSES. The `forge.gate.status` nodes of three runs share 1 Forge slot, while their `hyperunix.find` node runs without it: R074-FORGE. Under a mixed fan-out of three runs no pool exceeds its own limit, sampled and at the peaks: R074-SEPARATE. Without a budget the same three runs hold 6 agents at once, so the meter is live: R074-PER-RUN-CONTROL. A run takes its own permit first, and that permit still binds under a wider budget: for agents, R074-RUN-LIMIT; for the run's 16 node permits, R074-NODE-RUN-LIMIT. A call replayed from the resume journal takes no slot: R074-REPLAY-UNCHARGED. `peakInFlight` keeps the highest in-flight count the pool has reached when the load falls and rises again: R074-PEAK-IN-FLIGHT. Per pool the budget is a count and a first-in-first-out line, and a released slot passes to the oldest waiter: R076-UNIT-RELEASE.
- EAT-R075, the wait reason. A request that has to queue is told so through `onQueued` once per pool it queues on, at the moment it queues there, and never for a pool that admits it at once; the report names the pool, its limit, its in-flight count and the line ahead, with a wait of 0: R075-UNIT-REASON and R075-UNIT-REPORT-PER-POOL. A report that throws strands nothing: the request stays in line, is admitted when a slot frees or refused at the queue deadline, and leaves the line either way: R075-UNIT-THROWING-REPORT. `RunWorkflowOptions.onAdmissionWait` adds the call's kind and the position its progress row carries: R075-REASON and R075-WAIT-POSITION; one that throws strands no dispatch: R075-THROWING-WAIT-REPORT. `HostAdmission.waiting()` lists every waiting request under the pool it waits on, with that pool's limit, its in-flight count and the line ahead, in counts and pool names only, and its wait, measured on the monotonic clock, grows while the wall clock stands still: R075-UNIT-WAITING. While an agent waits, its wait passes 50 ms and no extra child is dispatched: R075-REASON. A lease carries the monotonic milliseconds from its request to its admission: R075-UNIT-REASON and R075-UNIT-LEASE-WAIT. Pools are taken one at a time in `HOST_ADMISSION_POOLS` order whatever order a request names them in, and a request waiting on its first pool holds none of the later ones: R075-UNIT-ORDER. A pool named twice is taken once, and a lease names its pools once each, in that order: R075-UNIT-DEDUPE.
- EAT-R075, the queue deadline. One queue deadline runs from a request's call across every pool it names. A request still waiting when its deadline's timer fires is refused with `admission-deadline`, naming the pool it waits on, hands back every pool it had taken and leaves the line: R075-UNIT-DEADLINE and R075-UNIT-WHOLE-WAIT. On the real clock the refusal is pinned between 20 ms before and 240 ms after a 400 ms deadline (R075-UNIT-DEADLINE-BOUND) and a 2000 ms deadline (R075-UNIT-DEADLINE-LONG), and between 20 ms before and 200 ms after a 500 ms deadline spent across two pools, of which the request reached its second about 380 ms in (R075-UNIT-WHOLE-WAIT). A tighter bound, and any bound on another deadline, is not claimed (RESIDUAL R1).
- EAT-R075, a refused dispatch. A refused agent or node is never dispatched. An agent's refusal answers its call with a fatal error carrying the refusal's text. Awaited directly, it fails the run with that text, naming the pool: R075-DEADLINE. Inside `parallel()` or `pipeline()` it fails the run the same way, because neither folds it into null: R075-AGENT-REFUSAL-FATAL. The agent's last row is in state `error` with the refusal's exact text, which the run's error carries too: R075-AGENT-REFUSED-ROW. It goes on record as an attempt that did not settle, so a resume of that journal runs it live: R075-REFUSED-ON-RECORD. A node's refusal answers its call with a fatal `unavailable` CapabilityError. Awaited directly, it fails the run with a CapabilityError whose message names `forge-operations`, the pool it waited on (R075-NODE-DEADLINE); inside `parallel()` or `pipeline()`, it fails the run with one whose message contains "Host admission refused" (R075-NODE-REFUSAL-FATAL). The refused node leaves an error row whose text contains "Host admission refused" and puts nothing new on record, no dispatched marker included; a refused override re-run carries the original effect row forward, so a resume still stops at the position: R075-NODE-REFUSED-RECORD. A script's own try/catch catches either refusal, the caught error's text containing "Host admission refused", and the run then completes: R075-REFUSAL-CAUGHT.
- EAT-R076, a cancelled wait. A run aborted while its agent, or its `forge.gate.status` node, is queued dispatches neither, and the slots return to zero once the holders release: R076-RUN-CANCEL and R076-NODE-CANCEL. A run that fails while two agents and a node of it are queued takes every one of those waits out of the line by the time it settles, and each hands back what it had taken: R076-RUN-END-EVERY-WAIT. A skip takes its agent's wait out of the line at once, before any sibling releases: R076-SKIP; and hands the run's own permit back, so the run's next agent reaches the line while the slot is still held: R076-SKIP-RUN-PERMIT. Each of those waits is counted in `cancelledWhileQueued`. A slot that arrives in the same tick its run ends, by abort or by failure, goes straight back undispatched, for a `forge.gate.status` node (R076-NODE-HANDOFF-ABORT and R076-NODE-HANDOFF-FAILURE) and for an agent (R076-AGENT-HANDOFF-abort and R076-AGENT-HANDOFF-failure); so does one that arrives in the tick its agent is skipped, which also hands the run's own permit back (R076-AGENT-HANDOFF-skip). An agent paused while queued hands the slots back when they arrive, with the run's own permit, and takes both again and starts on resume: R076-PAUSE and R076-PAUSE-RUN-PERMIT. A request cancelled on its second pool hands back the first: R076-UNIT-PARTIAL. Release hands the slot to the oldest waiter, and a second release of the same lease is a no-op: R076-UNIT-RELEASE. An already-cancelled request takes nothing and is never queued: R076-UNIT-PRE-ABORTED. A request naming no pool, an unknown pool, or an unknown pool beside known ones is refused with `unknown-pool` before taking anything: R076-UNIT-UNKNOWN and R076-UNIT-MIXED-UNKNOWN.
