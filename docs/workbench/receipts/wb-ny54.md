- EAT-R073. `runWorkflow` refuses a `concurrency`, `agentCap`, `itemCap` or `nestedCap` that is not a positive integer. The refusal is a `WorkflowRuntimeError` ("Workflow <name> must be a positive integer."), raised before a worker exists or anything is dispatched. Before this cut, 0, -1 and NaN parked every agent behind a semaphore with no permits, so the run hung; a fraction rounded up to the next whole permit; and Infinity left the run unbounded. An unset limit keeps its default, and the default concurrency is still `workflowConcurrency()`, clamped to [1, 16]. `HostAdmission` refuses each of its four limits the same way (`HostAdmissionError`, code `invalid-limit`, naming the limit), and its queue deadline stops at setTimeout's ceiling of 2147483647 ms.
- EAT-R074. A host builds one `HostAdmission` and hands it to every run it starts (`RunWorkflowOptions.hostAdmission`). It holds three pools with separately configured limits: `sdk-queries`, `child-processes` and `forge-operations`. `dispatchPools` states the charge. An agent dispatch is an owned SDK query and a host child. A node dispatch is a host child, and a `forge.*` node is also a Forge operation. A run takes its own permit first and the pools last, immediately before the dispatch, so nothing is awaited between admission and the spawn or node call. The budget is a counter and a first-in-first-out line per pool, not a second scheduler: it never orders runs against each other, never prioritises, retries or starts work. Pools are always taken in the same order, so two requests never wait on each other in a cycle.
- EAT-R075. A request that has to queue is told why, once per pool, through `onQueued`: the pool, its limit and load, and the line ahead. `RunWorkflowOptions.onAdmissionWait` adds the call's kind and position. `HostAdmission.waiting()` lists every queued request with its measured wait (monotonic, `performance.now()`), and a lease carries the wait it took. Past the queue deadline the request is refused, typed (`admission-deadline`, naming the pool), and leaves the line. The run then fails, as the agent cap fails it: an agent refusal is a fatal error, and a node refusal carries an `unavailable` CapabilityError diagnostic. Nothing is dispatched.
- EAT-R076. The run's end, an abort included, takes every queued wait of that run out of the line at once, and so does a skip. The request hands back every pool it had taken, is counted in `cancelledWhileQueued` and is never dispatched. A pause while queued hands the slots back when they arrive. A released slot passes straight to the oldest waiter.
