- What was red (the hazard, as measured): the retention key `<task.id>:<call.index>` is reused by a later attempt or turn of one `agent()` call. A runtime retry (`task.control.retry(index)` in `src/ui/workflow-menu.ts`; `src/workflow/runtime.ts` re-enters its loop with the same `index` and `agentId`, so the new query carries a NEW session id under the same key) and a resume (`src/workbench/claude-host.ts` `resumeAgent` fires `onSettled(result, previous.call)`: same key, same session id) both reuse it. `retain()` attempted the settle whenever ANY terminal was remembered for the key, so within the 15-minute TTL the earlier attempt's terminal made the later attempt's acknowledged interrupt be refused at `retain` (`foreign-observation` after a retry: the remembered terminal names the earlier session; `stale-observation` after a resume: it predates the acknowledgement) with the one diagnostic line and NOT parked, so that attempt's own later terminal settled nothing: no result phase was minted.

Ordering fact the remedy rests on (read in source at cut time): attempt N's terminal reaches `onTerminal` from `createClaudeObserver`'s `onSettled` (`src/workbench/claude-transcript.ts`), which the host calls synchronously after `await invoke(...)` and before `spawnAgent`/`resumeAgent` resolve (`src/workbench/claude-host.ts`); `src/workflow/runtime.ts` awaits that promise and runs its retry branch (`intent() === "retry"`, `attempt++`, `continue`) only afterwards, so the next attempt's system/init always follows the earlier attempt's remembered terminal and precedes its own terminal. Forget-on-init therefore never discards the current attempt's terminal.
