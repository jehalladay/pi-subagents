- Provider reading (EAT-R019). The wiring suite moves the user settings.json and a Git-ignored settings.local.json, and each one declines the recorded answer.
- Unknown readings (EAT-R020). A reading the host cannot take is unknown, with a fixed reason and no digest. While any reading is unknown, the host's `replaySafe` is false, so no agent answer and no node read comes back from the journal. A reading that claims measured without a well-formed digest counts as unknown. The pinned unknown cases are: a directory outside Git; a repository whose survey cannot account for a path (a committed symlink) although HEAD reads; an instruction or setting entry that is unreadable or not a file or directory; a directory cycle; a walk past the budget (2000 files, 32 MiB); an unrecognized setting source; and a missing or malformed invocation identity.
- Retained protection (EAT-R021). The uncertain non-read denial does not depend on the basis, and still does not. A settlement lost after a non-read dispatch resumes to the typed uncertain-effect with no second dispatch, under equal, changed and unknown readings alike. A settled write is refused under changed readings too. A journaled read comes back marked stale under equal readings and runs live under changed ones.

  - instruction bytes outside the listed locations: managed policy files, plugin-provided skills, files a memory file imports from elsewhere, and Git-ignored memory files below the cwd;
  - a dependency that changes inside one run after the host read it. The readings are taken once, when the run's host is built; the source is also held for the run by the identity re-check before each dispatch;
  - the detached host, which keeps no journal and so replays nothing;
  - a live SDK session. No model ran: the host suite injects the SDK query, and every wiring agent asks for worktree isolation, which the Claude host refuses before any query. A live call there settles to null, and a recorded answer can return only from the journal; the wiring suite plants that answer into the recording run's own journal row, keeping the row's real key and basis.
