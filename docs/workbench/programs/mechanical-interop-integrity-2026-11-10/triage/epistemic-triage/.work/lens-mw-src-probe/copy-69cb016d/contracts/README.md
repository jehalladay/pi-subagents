# Optional external entrypoint descriptors

This directory contains **data contracts only**. It is not an RPC server, scheduler, invocation runtime, or registry.

- `entrypoints/development.v1.json`: identifies a deployable function, required binding names and schema paths. Status is `descriptor-only`.
- `schemas/development-request.v1.schema.json`: syntactic input validation.
- `schemas/development-outcome.v1.schema.json`: coarse discriminator-level output validation, not Forge/HX/RF result verification.
- `entrypoints/coordination-reconcile.v1.json`: the one pure coordination export, `reconcile` of `@mechanical/workflows-coordination`, with `bindings: []` (PIWB-MW6-R001). Its schemas are `schemas/coordination-resolver-input.v1.schema.json` and `schemas/coordination-resolution.v1.schema.json`. Status is `descriptor-only`.

Local `develop(services, request)` does **not** require any descriptor. A future host adapter must verify executable artifact digest and native provider capabilities before accepting external calls. See [entrypoint specification](../docs/05-deployable-entrypoints.md).

## External function host interoperability audit (2026-11-04)

The [Pi Workbench program](../docs/programs/pi-workbench-interop-2026-11-04/README.md) audit found a schema-path mismatch between the descriptor and the host; it is repaired (PIWB-MW0-R001). The canonical schema-ref grammar is a bare filename (`development-request.v1.schema.json`, `development-outcome.v1.schema.json`) naming a file in `contracts/schemas/`; a directory segment or `..` traversal is refused with `ENTRYPOINT_CONTRACT_INVALID` before the loader runs. `apps/development-rig/test/entrypoint-descriptor-file.test.ts` reads this committed descriptor from disk and drives `invokeInstalledDevelopment` over the real npm-packed `@mechanical/workflows-development` tarball and `invokePinnedDevelopment`; the host tests no longer carry a handwritten descriptor copy. The descriptor field set is closed (PIWB-MW0-R002): `schema`, `id`, `implementation`, `inputSchema`, `outputSchema`, `bindings`, `status` and the single optional string annotation `note`; any other top-level key is refused with `ENTRYPOINT_CONTRACT_INVALID` before the loader or any install step runs, in both `invokePinnedDevelopment` and `invokeInstalledDevelopment`. `apps/development-rig/test/entrypoint-descriptor-closed.test.ts` names each denial class (parent traversal, absolute path, `https:`/`file:`/`data:` scheme, backslash, NUL and control character, absent canonical-form file, extra key) for both schema fields. Do not convert descriptor-only metadata into an authority to execute arbitrary package exports.

## Pure coordination function (PIWB-MW6-R001)

`apps/development-rig/src/coordination-host.ts` (`invokePinnedReconcile`) admits only the committed `coordination-reconcile.v1.json`: a descriptor with any binding, another export or package or id, an extra key, or a schema reference other than the two published filenames is refused `ENTRYPOINT_CONTRACT_INVALID` before the loader runs. The host verifies the pinned artifact digest (`ENTRYPOINT_ARTIFACT_MISMATCH`), validates the serialized input against the published input schema before load (`COORDINATION_INPUT_INVALID`), and validates the returned Resolution against the published output schema, including that the Resolution echoes the input basis and budget and that no admitted intent declares `authorized-effect` (`COORDINATION_OUTPUT_INVALID`). The schema validator implements only the keywords the two schemas use and refuses any other keyword. An intent that declares `authorized-effect` passes the input schema and the resolver rejects it `INTENT_AUTHORITY_EXCEEDED`. The host imports no process, file-write, service, Forge, Furnace or Beads path and never applies an admitted intent; `apps/development-rig/test/coordination-reconcile-host.test.ts` reads the descriptor and schemas from this directory and shows each refusal with the loader count at zero. This is a local function host with an injected loader: it is not Pi-callable, and the Pi-side function branch, admission grants and an installed-tarball consumer for the coordination package remain separate work.

## Proposed host binding `mechanical.pi-host/v1` (EAT-R002, EAT-R003)

`schemas/mechanical-host-binding.v1.schema.json` is the closed JSON schema of the proposed application-host binding `MechanicalHostBindingV1`; `apps/development-rig/src/host-binding.ts` is the single producer of the matching TypeScript type, the validator (`validateHostBinding`, `admitHostBinding`) and the canonical bytes. A missing field, an extra field, an unknown contract version or an unknown `evidenceProfile` or `contextProfile` is refused with a typed `HostBindingError` that names the field, and `admitHostBinding` reaches its injected loader only for a binding that passed. Pi's transport `hostMode` (`embedded`, `detached`) is a different axis and is not a binding field. `dispatchWriteAtFinalBoundary` starts the writer only when the exact candidate grant `mechanical:develop-write` is present at the final boundary; a prefix, a three-colon spelling, an absent grant and a grant revoked after admission each refuse with zero writer effects. The grant spelling and the contract version stay a proposal: the written joint ratification with Pi (P-contract) is a recorded condition that this cut does not fabricate, and the entrypoint status stays `descriptor-only`. `apps/development-rig/test/host-binding.test.ts` consumes the producer build and the committed schema and carries a guard that no second `MechanicalHostBindingV1` declaration exists.
