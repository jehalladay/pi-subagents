# 02 — Atomic requirements

Requirements are **flat**. IDs denote independently falsifiable claims, not a mandated implementation order. `CURRENT` is a repository-local scaffold obligation; `TARGET` is unimplemented until live evidence is recorded. Implementation status and evidence live in [10](10-current-state-and-gaps.md).

## Boundaries

- **MW-001 CURRENT** — Workflow authoring MUST support plain exported asynchronous functions without registration or an engine.
- **MW-002 CURRENT** — Direct function execution MUST NOT require a deployable entrypoint manifest.
- **MW-003 CURRENT** — A workflow MUST receive explicitly injected application dependencies; it MUST NOT discover Library files or SDK clients through global state.
- **MW-004 CURRENT** — Build, test, runtime and deploy operations MUST NOT depend on the Library repository, its checkout, or its file paths.
- **MW-005 CURRENT** — Root Forge workspace MUST register development library and development rig as separate members, and MUST NOT register the root package as its own member.
- **MW-006 CURRENT** — Repository root and members MUST declare real Forge build/test gates, not echo-only fake PASS.
- **MW-007 CURRENT** — New reusable packages MUST be extracted only when there is a concrete consumer; no mandatory workflow-core library. Evidence: `forge.workspace.toml` names exactly two members and `scripts/check-structure.ts` refuses any other roster; no workflow-core package exists (docs/11).
- **MW-008 CURRENT** — Forge/Furnace cores MUST NOT gain reciprocal dependencies via MechanicalWorkflows; semantic adapters MAY depend on both public SDKs. Evidence: neither member declares `@forge/sdk` or `@furnace/sdk` (`qa/integration/installed-consumer.ts` asserts the rig depends only on the library; `scripts/check-structure.ts` refuses literal optional-SDK imports); the SDKs are out-of-band links (docs/12).
- **MW-009 CURRENT** — Provider-specific tool packages MUST remain optional; no Claude-specific code inside provider-neutral SDK contracts. Evidence: `scripts/check-structure.ts` `LIBRARY_PROVIDER_IMPORT_FORBIDDEN` refuses any Forge/Furnace/HX/RF/model-provider import under `packages/development/src` and `packages/coordination/src`, naming the Pi module family explicitly (`@earendil-works/pi-*`, `@tintinweb/pi-subagents`, bare `pi-subagents`; EAT-R020 L1 scan leg), with red controls in `scripts/check-structure.test.ts`; provider adapters live only in the rig.

## Development function correctness

- **MW-010 CURRENT** — Invalid task/workspace/base revision MUST be refused before a dependency callback executes.
- **MW-011 CURRENT** — Incomplete/unknown scope coverage MUST prevent implementation and report a needs-evidence outcome.
- **MW-012 CURRENT** — Scope and compiled context MUST match requested input basis before the next effect.
- **MW-013 CURRENT** — Candidate MUST name the original parent basis and a nonempty, distinct candidate revision. A live Git adapter MUST additionally confirm the candidate source tree actually differs from its parent.
- **MW-014 CURRENT** — Verification MUST name the candidate basis, not the request's obsolete source basis.
- **MW-015 CURRENT** — `partial`, `unknown`, source mismatch, or missing verification reference MUST NOT produce `verified_candidate`.
- **MW-016 CURRENT** — An established failing verification MUST remain a valid domain failure result, distinct from a transport failure.
- **MW-017 LIVE WITNESSED 2026-10-15** — A live Forge adapter MUST preserve all native status/verdict axes, stable reason codes and artifact/operation references; any reduced app outcome MUST reference original evidence. (`qa/integration/2026-10-15-live-forge-gate.md`, `qa/integration/2026-10-15-furnace-process-host.md`) The live gate classifier keeps status, verdict, disposition, terminal fact, gated basis and operation id as separate axes with stable reason codes; the Furnace FAIL control caught and fixed the terminal-fact regression the same day (MW-060).
- **MW-018 BOUNDED LIVE WITNESSED 2026-10-15** — A live HX adapter MUST preserve coverage/bounds and MUST NOT convert partial queries to complete empty sets. (`qa/integration/2026-10-15-combined-live-composition.md`) A real incomplete `hx dependencies` answer became `partial` with its positive paths retained and no invented evidence; the composition stopped before RF, agent and Forge. A complete task-scoped answer remains an upstream HyperUnix gap (beads 6ml/4vw).
- **MW-019 BOUNDED LIVE WITNESSED 2026-10-15** (`qa/integration/2026-10-15-native-hx-rf-observations.md`) — A live RF compiler MUST preserve render/input basis, model budget/provenance, and acknowledge its runtime's actual completion support. Native RF 0.1.583 rendered the task and source commit with model capability verified; a bounded RF→agent→Forge cut passed. Distributed RF profiles remain separate targets.
- **MW-020 LIVE WITNESSED 2026-10-15** — A real implementation agent MUST operate in an explicitly bound workspace; its edits/effects MUST be reconciled after ambiguous termination. (`qa/integration/2026-10-15-furnace-and-agent.md`, `qa/integration/2026-10-15-candidate-selection.md`) Agents run in an explicitly bound package root or an isolated candidate worktree; an unchanged HEAD, a dirty tree or a stale basis after the agent stops the journey with a reconciliation reason instead of a gate.

## Optional deployable invocation

- **MW-021 CURRENT** — An entrypoint descriptor MAY describe one exported function, input/output schemas and required binding names without causing execution.
- **MW-022 LOCAL WITNESSED 2026-10-15** — Hosts MUST pin immutable executable artifact identity, entrypoint and contract version before admission. (`apps/development-rig/test/installed-host.test.ts`, `qa/integration/container-worker.test.ts`) A real local tarball is admitted only with its SHA-256 digest, declared entrypoint and contract version; a wrong digest refuses before install, load or any callback. No remote target has been supplied (WP-K/WP-O).
- **MW-023 LOCAL WITNESSED 2026-10-15** — Hosts MUST validate external input, allowed entrypoint and capability bindings before invoking user code. Input schema, allowed export and capability bindings are checked before the loader runs (`entrypoint-host.test.ts`: extra input field, missing binding, foreign capability and wrong export all refuse with zero loads).
- **MW-024 CURRENT** — Host-owned SDK clients MUST be released by that host; borrowed clients MUST never be silently closed by workflow functions. Evidence: library functions receive callbacks only and own no client; the rig opens and closes its own Forge connection per gate (`live-gate.test.ts`: incompatible negotiation closes the connection; the Furnace process executor opens one connection per Attempt).
- **MW-025 LOCAL WITNESSED 2026-10-15** — A host MUST NOT claim durable execution when it only supports transient invocation. Every host labels its guarantee: CLI `mode` fields, the receipt `furnace` stage (`not_run` locally) and the Furnace process receipt `guarantee` line; docs/14 and the process-host report state what Furnace does and does not persist.
- **MW-026 CURRENT** — Agent/framework-specific registration MUST remain inside adapters for that framework. Evidence: the only `ExecutorApp` registration is `apps/development-rig/src/furnace-app.ts`; Claude adapters are `claude-*.ts` in the rig; the library carries none (`LIBRARY_PROVIDER_IMPORT_FORBIDDEN`).
- **MW-027 LOCAL WITNESSED 2026-10-15** — Remote invocation input MUST NOT serialize live SDK clients, file descriptors or credentials. The entrypoint input schema is closed: an extra field (the test uses `secret`) refuses before the loader; requests carry a workspace id, a revision and a task, never clients, descriptors or credentials.
- **MW-028 LOCAL WITNESSED 2026-10-15** — A deployment artifact MUST run without a MechanicalWorkflows source checkout or Library. (`qa/integration/container-worker.test.ts`) A read-only, network-less Amazon Linux container with only the Forge-built tarballs and Node ran the pinned host without a source checkout or Library.
- **MW-029 LIVE WITNESSED 2026-10-15** — Malformed external output MUST be reported as invalid/incomplete, not as domain success. Malformed or contradictory native output stays invalid: a bare cancelled envelope, an inconsistent PASS axis set, a reviewer report that is not JSON and an entrypoint result without a producer ref are all refused (`live-gate.test.ts`, `claude-review.test.ts`, `entrypoint-host.test.ts`; live: `qa/adversarial/2026-10-15-forge-gate-cancel.md`).
- **MW-030 LOCAL WITNESSED 2026-10-15** — Package version changes during an operation MUST NOT silently switch the code used by a retry. The admitted artifact digest is pinned before and after `npm install` (`installed-host.test.ts`); a retry that presents another digest refuses before load. A remote retry has not been exercised (no target).

## Effects, nesting and recovery

- **MW-031 TARGET** — A Furnace Run establishment call whose outcome is uncertain MUST NOT be blindly repeated as a new start. No MechanicalWorkflows code establishes Furnace Runs; `furnace run start --request-id` is the establishment authority and the process-host journeys used distinct request ids. Stays TARGET until a programmatic establishment path exists (fvh).
- **MW-032 TARGET** — Once Furnace provides native replay-safe establishment, stable logical key plus equal specification MUST identify one Run; same key plus conflicting specification MUST refuse.
- **MW-033 TARGET** — A child logical key MUST be stable across parent Attempt retries, and distinct for intentionally distinct child work.
- **MW-034 LIVE WITNESSED 2026-10-15** — Caller wait timeout MUST NOT automatically mean operation cancellation. (`qa/adversarial/2026-10-15-forge-gate-faults.md`, `qa/adversarial/2026-10-15-forge-gate-cancel.md`) A killed controller and a transport closed after dispatch left the native gate to settle on its own; only an explicit `operation.cancel` cancelled, and the host never retried.
- **MW-035 CURRENT** — Parent cancellation MUST NOT cascade to children without explicit authority and policy. Evidence: no cascading cancellation exists in shipped code; the only cancellation exercised was an explicit `operation.cancel` of the named operation (cancel QA).
- **MW-036 LIVE WITNESSED 2026-10-15** — Recursive operations MUST NOT occupy all shared capacity while synchronously awaiting child work when this would prevent progress; use native workflow readiness/wakeups or explicit resource configuration. (`qa/performance-2026-10-15.md`) Two one-slot concurrent gates: the queued run measured its slot wait natively (`data.intervals.queued`) and neither verdict was affected; the host never busy-waits for a child.
- **MW-037 LOCAL WITNESSED 2026-10-15** — Reconciliation MUST use authoritative product records; a MechanicalWorkflows receipt MUST NOT act as a parallel execution registry. Receipts are descriptive (`receipt.ts`: "do not use this in place of the workflow domain outcome"); Beads claims re-read the authoritative issue (`beads-claim.test.ts`); Furnace never reads the process receipt (process-host report).
- **MW-038 CURRENT** — Native Run/Work/Attempt, operation, workspace, and artifact identities MUST remain distinct from trace IDs and tool-call IDs. Evidence: receipts keep Forge operation ids, agent session ids, Git revisions, RF render ids and Furnace Run/Attempt ids in distinct fields (`receipt.test.ts`: a Git identity cannot masquerade as an agent session ref).
- **MW-039 CURRENT** — Cross-system correlation MUST represent proven causal relations without fabricating missing parents or completeness. Evidence: receipt stages are `established`, `observed`, `unknown` or `not_run`; a Forge PASS for another commit stays `observed` (`receipt.test.ts`); evidence audits bind lineages by ids (`qa/integration/mw-coverage-audit.ts`).
- **MW-040 LIVE WITNESSED 2026-10-15** — A parent function's failure MUST NOT imply its separately established durable child is stopped. (`qa/adversarial/2026-10-15-forge-gate-faults.md`) A SIGKILLed controller printed nothing while its orphaned native gate settled and the next gate passed at the same commit.
- **MW-041 LIVE WITNESSED 2026-10-15** — A shared child execution MUST NOT be cancelled merely because one observer detaches. Same witness: the observer's death did not cancel the Forge operation; the only cancellation came from an explicit `operation.cancel`.
- **MW-042 CURRENT** — RCP continuation MUST be opt-in; a durable Furnace host alone MUST NOT claim JavaScript stack continuation. Evidence: no code or document claims stack continuation; docs/14 and the process-host report say Furnace persists the Run/Attempt record only.

## Verification rule

A requirement graduates from target to current only with shipped files, a direct positive test, a deliberately falsifying negative control, and a public consumer-facing explanation. Implementation agents may work concurrently on any unfulfilled clause; this document does not specify a sequential roadmap.
