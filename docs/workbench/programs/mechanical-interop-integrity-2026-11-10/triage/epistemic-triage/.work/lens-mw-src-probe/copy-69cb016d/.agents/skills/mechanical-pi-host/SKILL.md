## Current, not aspirational

- Core `develop(services,request)` is an ordinary function with `discover`, `compileContext`, `implement`, `verify`. Preserve the four domain outcomes.
- The committed descriptor was **fixed** in `1f29daa7` and a packed-tarball regression test now reads it. Do not re-open the old mismatch as current P0. Test source exists; this skill does not certify a current test run.
- `invokeInstalledDevelopment` is a transient local, SHA-256-pinned, in-process **trusted** code loader; it does not give Pi a stable callable rig-host export, sandbox, durable worker or authorization.
- The 2026-10-15 Claude/Git/Forge and Furnace receipts are bounded historical real producer evidence, not Pi→Mechanical acceptance.
- `signal?: AbortSignal` prevents pre-dispatch effects; `developLive` now emits typed post-dispatch abort/lost-ack uncertainty, and `runClaudeImplementation` forwards the host signal into the SDK session through its public `options.abortController` (only when a signal is supplied) and stops reading an aborted SDK stream. `sdkAbortControlSupport` reports from the installed SDK's own declarations whether that control exists; a live abort test must skip with that reason, never pass, when it does not. That is **not** transaction rollback or automatic cross-host reconciliation. The `invocation` record carries fifteen axes: source commit/tree, SDK version, canonical settings, prompt, host-named skills and gate manifest, plus nine cross-host axes (workspace realpath, task digest, principal/session, Pi invocation id, descriptor and tarball digests, context and evidence profiles, gate parameters). The host states the last-listed host axes through `LiveDevelopmentOptions.hostIdentity`; an axis it leaves unstated stays `null` in `missingAxes`, and `assertReplayable`/`requireReplay` refuse with `INVOCATION_REPLAY_AXIS_MISSING` naming it. The opt-in `effectIntent` store (`fileEffectIntentStore`, schema `mechanical.effect-intent/v1`) persists one `uncertain` intent before the writer dispatches and settles it only against the committed tree and gate-definition hash. Disclosed limits: the CLI passes no store and no host axes, so nothing is recorded there; the disposable-child crash harness has not run; the record remains app-local identity, not a complete Pi replay proof.
- `onProgress?: ProgressCallback` on `developLive` reports `discovery`, `context`, `sdk_startup`, `first_edit`, `commit`, `gate_dispatch`, `settlement` in that order, each with its receipt stage (`rigStage`, mapping table in docs/06), a non-null disposition (`none`, `uncertain`, `settled`) and the latest native refs; it observes only and a throwing callback changes no outcome (EAT-R015). The receipt `sdk.version` is a semver string read from the installed manifest at run time (a non-semver manifest version is refused before dispatch, EAT-R032).
- Pi's registered `workflow_execute` still rejects `function`, but Pi has existing descriptor, function-authority and source-admission modules; they are not wired. The earlier worktree-preservation and two detached-grant defects have implementation/test corrections; the Claude host rechecks run abort after awaited startup. Retain and broaden fault tests rather than repeat old present-tense defects.
- Installed HX task scope was probed 2026-11-06 and is unsupported at that producer pin. Git census is allowed as a separately labeled first vertical. Pi RF `--no-commit` preview is never committed render provenance.
