# @mechanical/workflows-coordination

Pure, typed coordination policy ports for the collective-adaptation program (`docs/programs/collective-adaptation-2026-10-16`, milestone M0). A policy is an ordinary synchronous function from an immutable observation, a local memory and a `PolicyContext` to a `Proposal`: typed intents, updated memory and a trace. Nothing in this package performs an effect: no file write, no process, no network, no SDK import. A proposal is **not** an authorized effect; the resolver decides which intents are *admissible* against one pinned basis, protected scopes and an aggregate budget, and the host that owns native authority (Furnace, Beads, Forge, Git) executes admitted intents and reports receipts.

This package **does not** schedule work, store events, talk to any product, or claim live verification. Fixture environments it ships are labelled `fixture` and cannot be relabelled.

```ts
import { reconcile } from "@mechanical/workflows-coordination";
const resolution = reconcile({ basis, budget, protectedScopes: ["global:release"], proposals: [p.propose(observation, memory, context)] });
// resolution.admitted, resolution.rejected (stable codes), resolution.conflicts, resolution.budgetUsed
```

Rejection codes are stable diagnostics: `INTENT_BASIS_STALE`, `INTENT_SCOPE_PROTECTED`, `INTENT_WRITE_CONFLICT`, `INTENT_BUDGET_EXCEEDED`, `INTENT_DUPLICATE`, `INTENT_AUTHORITY_EXCEEDED`, `INTENT_CLAIM_INVALID` (a claim dimension that is NaN, negative or infinite; checked per intent before the conflict and budget passes). Two intents whose write scope interferes with another intent's read or write scope in the same batch are **both refused** and listed under `conflicts`; the resolver never picks a winner by an undisclosed tie-breaker. Admission order is disclosed: proposals in the order given, intents in proposal order.

## Composition operators

`sequential(p, q)` (Q observes `{ observation, prior: P's proposal }` under the same basis), `parallel(p, q)` (both evaluated independently; proposals collected, never reconciled here, so a scope interference stays visible to `reconcile`), `guarded(p, guard, q)` (Q runs only when the declared, versioned guard accepts P's proposal; a rejected guard leaves Q's memory untouched and is traced by `id@revision`), `alternative(p, q, selector)` (exactly one runs; the declared, versioned selector's choice is the first trace line) and `inhibit(p, q)` (an evidence-backed `inhibit` intent of P on a `scope` target removes Q's intents that write that scope; an inhibition without evidence is ignored and traced). Every operator is itself a pure policy whose memory is the pair of its parts' memories. Equivalence laws hold over the **intents payload** of payload-only policies (sequential associativity, parallel commutativity up to intent order), never over effects or shared external state; the tests state which. Inhibition only removes proposals: it can never admit, authorize or exempt an intent from the resolver or the host.

`repeated(option, spec)` is the sixth operator (`Repeated P*`, MWCOL-002): a bounded reactive option. Time is the count of evaluations, carried in the operator's own `RepeatedMemory` (`active`, `steps`, `holdLeft`, `latched`, the option's memory; `initialRepeatedMemory(m)` builds the start), never a clock, so the operator stays pure. The declared, versioned `RepeatedSpec` names `initiate(observation, context)` (the initiation gate and, while a run is active, the continuation guard), `terminate(proposal)`, `maxSteps` (positive integer) and `hold` (non-negative integer); anything else is refused at construction with `REPEATED_INVALID_SPEC`. A false gate proposes nothing, returns the memory object unchanged and traces `repeated-not-initiated`. A true gate starts a run (`repeated-initiated`); each evaluation of an active run executes one repeat of the option on the current observation and withholds its intents (`repeated-continuing`) until `terminate` accepts a repeat, which proposes only that repeat's intents and ends the run (`repeated-terminated`, with the repeat count). Reaching `maxSteps` repeats without termination is `REPEATED_NONQUIESCENT`: the run proposes no intent at all, traces `repeated-nonquiescent`, and latches until the guard has dropped once. Hysteresis: when the guard drops, an active run survives `hold` more evaluations (`repeated-hysteresis-held`, naming the evaluations left) and then releases without proposing (`repeated-released`); a true guard refills the hold. Each held evaluation still executes one repeat of the option, so a termination reached during the hold proposes that repeat's intents and ends the run (`repeated-terminated`) instead of releasing without a proposal. The operator proposes only and the option and the gate receive the whole common context unchanged, so `reconcile` and the host keep every admission decision.

## Landing-queue fixture

`runLandingQueue({ seed, candidates, lanes, steps, policy })` simulates candidates waiting to land on a moving head behind an independent gate: the gate verdict is a seeded xorshift32 draw (`gateDraws`, three of four pass; the stream starts from the seed run through a splitmix32 finaliser, `gateStreamStart`, so the first draw is a well-mixed function of the whole seed), the head is a counter, every transition is a pure function of the previous state, and each step records the observation digest, the proposed intent ids, the full `Resolution`, the applied events (`landed`, `gate-failed`, `restacked`, `refused` with the resolver code) and the state hash. The episode (`schema: "mw.landing-queue.fixture.v1"`) is labelled `mode: "fixture"` at the episode and at the state, and `labelEpisode` refuses any other label with `EPISODE_MODE_UPGRADE_FORBIDDEN`. Two deterministic policies ship: `fifoLanding` lands the oldest candidate on the head and proposes nothing once the head moves, which reproduces the merge bottleneck (one landing, then starvation); `restackFirst` restacks the oldest stale candidate before landing. `oracleLandedOrder` is an independent plain-loop oracle over the same seed and draw sequence; the tests require the harness and the oracle to agree on the landed order. `qa/integration/python-consumer/fixtures/landing-queue-seed7.json` holds the seed-7 `restackFirst` episode as canonical JSON; a TypeScript test pins it against regeneration and a Python test recomputes its hash, so both languages pin one byte sequence.

`runCompactionInheritance({ seed, tasks, policy })` simulates the compaction-inheritance environment (`schema: "mw.compaction-inheritance.fixture.v1"`, `mode: "fixture"`): one worker replacement and one downstream task per step, where only the summary a policy persists survives the replacement. A seeded draw (one `gateDraws` value per step, a third corrupt) alters the survivor's bytes before the policy observes it, so the provenance digest recorded at compaction (`summaryProvenance`, a digest over the source and the bytes) no longer matches. Typed intents are `persist`, `omit`, `route`, `annotate` and `compact`; the events are `replaced`, `corrupted`, `persisted`, `omitted`, `routed`, `annotated`, `compacted`, `downstream-failed` and `refused`. `persistAll` persists unchecked and reproduces the failure (a `downstream-failed` event naming the recorded and recomputed digests); `provenanceChecked` recomputes the digest, omits a mismatch with the digests as evidence and routes a rediscovery. Cost is 1 per clean task, 2 per rediscovery and 4 per failure, score is 3 per completed task minus total cost. `oracleCompactionOutcome` is an independent plain-loop oracle over the same draw sequence, and `labelCompactionEpisode` refuses any other label with `EPISODE_MODE_UPGRADE_FORBIDDEN`. `qa/integration/python-consumer/fixtures/compaction-inheritance-seed7.json` holds the seed-7, eight-task `provenanceChecked` episode as canonical JSON, pinned by a TypeScript test and re-verified in Python (every summary digest, the cost replay).

Requirements covered: MWCOL-001 (pure ports), MWCOL-002 (composition only where testable; conflicting parallel intents refused, never silently both committed), MWCOL-003 (seed, state hash, event history, independent oracle for the landing queue), the fixture half of MWCOL-004 (a fixture result cannot be labelled live), and the resolver contract of `06-coordination-policy-algebra.md`. Not covered here: the live adapters, episode export for training, learning hooks.

`canonicalJson` and `digest` refuse values JSON cannot carry faithfully with `CANONICAL_JSON_UNSUPPORTED_VALUE`: functions, symbols, bigints, NaN, both infinities and non-plain objects (Date, Map, Set, class instances) throw a `TypeError` naming the offending type instead of rendering `null` or `{}`, so no refused value collapses onto another value's digest. The guarantee is narrower than "every distinct pair of values digests differently": an array hole and an explicit `null` canonicalise to the same bytes (JSON has no hole), `-0` and `0` render as the same number, and `undefined` object members are dropped, so those pairs do share a digest. Every Python consumer leg imports one `canonical_json` (`qa/integration/python-consumer/mw_canonical.py`) that serialises with `allow_nan=False` to refuse the same numbers.

`runElasticLanding` (CA-R2, `src/elastic-landing.ts`) adds elastic integrator lanes to the same environment without touching the plain runner: lanes are active or paused state, changed by budgeted `lane.allocate`, `lane.reserve`, `lane.pause` and `lane.route` intents through `reconcile` and by seeded interruptions, each change an event with step and reason. `elasticLanes` is the elastic policy, `fifoLanding` and `restackFirst` the baselines, and `oracleLoadBounds` the independent Load-row oracle; a scenario no scheduler can finish is reported as `LOAD_INFEASIBLE`, not as a policy failure. Its seed-7 episode is pinned in `fixtures/landing-queue-elastic-seed7.json`.

## Quorum-evidence fixture

`runQuorumEvidence({ seed, candidates, reviewers, steps, budget, gate, policy })` simulates a quorum deciding which candidate patches to commit. Each candidate has a hidden true quality; its reviewers' votes share a seeded noise term, so a correlated candidate collects unanimous approval whatever its quality and a majority of correlated votes is not independent evidence. Evidence has a price charged against `budget` through the resolver (`inspect` 1, `challenge` 2, `test` 3), and the five typed intents are `inspect`, `test`, `challenge`, `abstain` and `commit`. The native gate stays authoritative: a `test` of a good, non-flaky candidate issues a gate receipt, and with `gate: "authoritative"` every `commit` scope of a candidate without one is protected, so the resolver refuses the commit with `INTENT_SCOPE_PROTECTED` and the refusal lands in the event history. `gate: "ablated"` removes that check and exists only to expose the false positive it prevents; the choice is part of the hashed state. Penalties are plain counters in the state: 10 per committed bad patch and 2 per commit attempted with no independent test. Two deterministic policies ship: `majorityVote` inspects the votes and commits on a majority (so correlated votes reproduce the false positive when ungated and an uncalibrated refusal when gated), and `independentTestFirst` spends one test before any commit, commits only a passing candidate and abstains once the resolver refuses a test with `INTENT_BUDGET_EXCEEDED`. `oracleQuorum` re-derives the world from the seed in plain loops and must agree with the harness on decisions, false positives, spend and penalty. The episode (`schema: "mw.quorum-evidence.fixture.v1"`) is labelled `mode: "fixture"` and `labelQuorumEpisode` refuses any other label with `EPISODE_MODE_UPGRADE_FORBIDDEN`. No process, network or QuorumCLI is touched. `qa/integration/python-consumer/fixtures/quorum-evidence-majority-ablated-seed0.json` and `quorum-evidence-independent-seed7.json` hold the two pinned episodes as canonical JSON; TypeScript tests pin them against regeneration and `test_quorum_fixture.py` recomputes their hashes and counts.

## Colony resilience fixture (M1, family 5)

`runColonyResilience({ seed, workers, compute, steps, policy })` simulates a seeded world in which workers are killed, signals are poisoned (the world marks them `nonauthoritative`), receipts go stale (their basis predates the head), graph mutation is denied on protected scopes and the compute budget runs out; all of it derives from `gateDraws(seed)`. Intents are typed `retry` (recover and accept on cited evidence), `reassign` (recover onto a spare, one compute), `verify` (one compute, a fresh authoritative receipt, then accept), `quarantine` (mark a signal untrusted) and `halt`. Accepting on a nonauthoritative signal or a stale receipt is an unsafe effect, counted and recorded as an `unsafe-effect` event; `classifyEvidence` returns `unknown` for such evidence and `verified` only for an authoritative signal with a receipt on the head. The resolver refuses protected-scope mutation (`INTENT_SCOPE_PROTECTED`, which also marks the worker denied in the next observation) and budget overrun (`INTENT_BUDGET_EXCEEDED`); both appear as `refused` events. Two deterministic policies ship: `naiveRetry` trusts everything and reproduces the unsafe effects, `receiptChecked` treats unknown evidence as unknown, verifies before accepting and halts, with an explicit `halted` event, on exhaustion or when only denied workers remain. `oracleColonyOutcome` is an independent plain-loop oracle over the same draws (unsafe-effect count, recovered workers, spend, terminal group); `colonyOutcome` reads the same facts off a harness state. Trail and Quorum appear only as `fakes: { trail: "absent", quorum: "absent" }`, never invoked (MWCOL-006). The episode (`schema: "mw.colony-resilience.fixture.v1"`, `mode: "fixture"`) cannot be relabelled (`labelColonyEpisode` refuses with `EPISODE_MODE_UPGRADE_FORBIDDEN`), and `qa/integration/python-consumer/fixtures/colony-resilience-seed29.json` pins the seed-3 `receiptChecked` episode as canonical JSON in TypeScript and re-hashes it in Python.

## Artifact-recovery fixture

`runArtifactRecovery({ seed, work, steps, policy, arm?, corruptArtifact?, inheritedArtifact? })` simulates one failed attempt and its successor (MWCOL-003 failure injection, MWCOL-007 cross-attempt continuity). Producer `a1` does partial work and crashes at a seeded step, leaving a snapshot artifact (`artifact-a1`, progress one unit short of the crash, with a provenance digest from `artifactProvenance`); successor `a2` (parent `a1`) must finish the `work`-unit task. A seeded intervention flag decides whether the artifact stays (treatment, id `treatment:artifact-kept`) or is removed (control, id `control:artifact-removed`); `arm` forces it, and the episode only records the id for a later data rung to consume. Attempt lineage (id, parent, outcome, consumed artifact ids and digests) is part of the state, and creation, removal, consumption, refusal and unavailability of the artifact are events (`artifact-created`, `artifact-removed`, `artifact-consumed`, `artifact-refused`, `artifact-unavailable`), next to `crashed`, `worked`, `completed` and resolver `refused`. Two deterministic policies ship: `restartFromScratch` ignores the artifact and pays the full `work` steps in both arms; `resumeFromSnapshot` consumes the artifact when it is present and its provenance digest matches (one step), otherwise records `artifact-unavailable` with the reason (`absent` or `digest-mismatch`) and restarts. The environment is the authority: a consumption of a missing or digest-mismatched artifact is refused with an `artifact-refused` event whatever the policy believed, and the refused step still costs a step. `oracleRecovery` is an independent plain-arithmetic oracle over the same draw sequence (crash step, arm, steps to completion); the tests require the harness and the oracle to agree. The episode (`schema: "mw.artifact-recovery.fixture.v1"`) is labelled `mode: "fixture"`, `labelRecoveryEpisode` refuses any other label with `EPISODE_MODE_UPGRADE_FORBIDDEN`, and a run with `work` below 4 or non-integer `seed`, `work` or `steps` is refused with `ARTIFACT_RECOVERY_INVALID_RUN`. `qa/integration/python-consumer/fixtures/artifact-recovery-seed7.json` holds the seed-7 treatment episode under `resumeFromSnapshot` as canonical JSON, pinned by a TypeScript test and recomputed by a Python test. An `inheritedArtifact` (the artifact an earlier episode's failed attempt left, with its `originEpisode`) replaces the episode's own snapshot as the one the successor may consume; a digest that does not match the content is refused before any step with `ARTIFACT_INHERITED_DIGEST_MISMATCH`, and the episode and its final state record `inheritedFrom` (absent when nothing was injected). Time stays out of it: the deferred `Repeated P*` operator is not part of this slice.

## Shared episode format (mw.episode.v1)

`toEpisode(environmentEpisode)` converts any of the five fixture environment episodes (`LandingQueueEpisode`, `CompactionInheritanceEpisode`, `ColonyEpisode`, `RecoveryEpisode`, `QuorumEvidenceEpisode`) into one typed, versioned `Episode` (`schema: "mw.episode.v1"`, `version: 1`); `packages/coordination/schema/episode.v1.schema.json` is its JSON Schema. The record carries the episode id, task basis and family, a policy configuration hash (`digest` of the `id@revision` tree), worker roles, the per-step state-hash checkpoints, each sampled decision with its eligibility set (the admitted and rejected intents of the `Resolution`, rejections with their stable code), read-set and evidence provenance, artifact creation and consumption, attempt lineage, cost (step count and summed budget spend; no wall clock), a verifier receipt labelled `fixture` (or `replay` for a replayed tape), and control/treatment ids. A value the environment does not know (a log probability no deterministic policy reports, the lineage of an environment without attempts) is the explicit literal `"unknown"`, never omitted, defaulted or `null`. The converter reads its input and never alters it. `mode` is the closed enum `fixture | replay | live`; `labelEpisodeMode` keeps or lowers a label and refuses every upgrade (fixture to replay, replay to live, anything to `live-verified` or to a label outside the enum) with `EPISODE_MODE_UPGRADE_FORBIDDEN`. `sanitizeValue` drops credential-shaped fields, replaces credential-shaped string values with `[redacted]` and returns the JSON-pointer paths it removed; `toEpisode` runs it before returning and records the paths in `sanitize.removed`. `episodeBytes` is the canonical JSON plus one newline, and one exported episode per environment is pinned under `qa/integration/python-consumer/fixtures/episode-*.json`: a TypeScript test regenerates and validates each against the schema, and `test_episode_fixture.py` re-hashes each in Python. The exports are fixture results and never count as native PASS.

## Replay adapter (mw.replay-tape.v1)

`replayTape(tape)` (collective-adaptation M2, the replay half of MWCOL-004) turns a captured tape of native receipts into replay-labelled observations and one shared `Episode` (`mode: "replay"`, `environment: "native-replay"`, verifier label `replay` over the tape digest). A tape (`schema: "mw.replay-tape.v1"`, `version: 1`, `tapeId`, integer `seed`, optional `basis`, `entries`) is JSON: each entry names an `id`, a `system` (`forge`, `beads`, `furnace` or `hx`), a `subject`, a non-negative integer `revision`, a `kind` and the `native` payload exactly as captured, which the observation retains verbatim beside its `nativeDigest`. Projection keeps native facts as they were: a Forge `failed` record is `FAIL` and `indeterminate` is `COULD_NOT_JUDGE`; a dirty candidate keeps `clean: false` and a PASS on it does not certify; HyperUnix coverage that is missing replays as `unknown`, `incomplete` stays incomplete, and only `complete` coverage with exit 0 certifies; a Furnace envelope must carry `protocol_version` 1 and an `ok: false` run stays uncertified. An entry that records an irreversible effect (`effect`) is projected as the recorded outcome only (`recordedOnly: true`, `effectReexecuted: false`); the module has no effect surface and a test pins that it imports only `./canonical.js` and `./episode.js`. An unrecognised tape version, system, receipt shape or envelope version throws `REPLAY_TAPE_UNSUPPORTED`. A byte-identical duplicate entry is dropped (replaying twice yields identical canonical episodes), a reused id with different content is a `REPLAY_CONFLICT_DUPLICATE_MISMATCH` conflict and a revision below the one a subject already reached is a `REPLAY_CONFLICT_STALE_REVISION` conflict; neither is applied. `labelEpisodeMode` still refuses every upgrade of a replay episode with `EPISODE_MODE_UPGRADE_FORBIDDEN`. Replay episodes are not live evidence and never count as native PASS. The episode record gained the `native-replay` environment and the `replay` verifier label (schema `enum`s), nothing else.

## Decision-tape replay (mw.decision-tape.v1)

`recordDecisions({ environment, run, policy })` tapes one fixture environment run and `replayDecisions(environment, tape)` re-executes that environment from the recorded intent sequence alone (collective-adaptation 05 Replay row, MWCOL-004; this is not the receipt replay of `replayTape`: it re-runs a seeded fixture rather than projecting captured native receipts). A tape (`schema: "mw.decision-tape.v1"`, `environment` one of `landing-queue`, `compaction-inheritance`, `colony-resilience`, `artifact-recovery` or `quorum-evidence`, the `run` parameters without the policy, the policy `id` and `revision`, and `steps`) records at every step the full proposed `intents`, the `observationDigest`, the `admitted` intent ids and the environment `stateHash`. Replay drives the environment with a policy that has no logic and returns the recorded intents, then compares step by step in the order step number, observation, intents, admitted, checkpoint; the first disagreement returns `divergence` with code `REPLAY_DECISION_DIVERGED`, the step and the field (`step`, `observation`, `intents`, `admitted`, `checkpoint`, or `length` when the tape stops before or runs past the re-execution). A tape whose step numbers differ from the re-execution's (renumbered steps, a gap such as 1,2,4, or a tape that does not start at step 1) is not refused: it diverges on field `step` at the first tape step whose number disagrees, reporting that tape step number. A tape the module does not understand (unknown schema, an environment that does not match the tape, an unrecognised or ill-typed run parameter, a malformed step) throws `REPLAY_DECISION_TAPE_UNSUPPORTED`. The result `episode` is the shared `mw.episode.v1` record labelled `replay` (episode id prefix `replay:`, verifier label `replay`, receipt digest over the tape, verdict `replayed=<n>,diverged=none` or `diverged@<step>`); `labelEpisodeMode` refuses every upgrade of it, `live` included, with `EPISODE_MODE_UPGRADE_FORBIDDEN`. Every committed seed fixture replays to the same checkpoints as its committed episode. The module imports only sibling coordination modules and holds no effect surface. `qa/integration/python-consumer/fixtures/decision-tape-landing-queue-seed7.json` and `episode-decision-replay-landing-queue-seed7.json` are pinned byte for byte by a TypeScript test and re-hashed in Python (`test_decision_replay_fixture.py`) against the independent seed-7 episode. Replay episodes are fixture re-executions, never live evidence and never native PASS.

## Off-policy training export (mw.training-export.v1)

`exportEpisodeForTraining(episode)` is a pure function from the shared `Episode` to one `TrainingExport` (`schema: "mw.training-export.v1"`, `version: 1`) with one `TrainingStep` per decision: the sampled intent ids, the eligibility `mask` (the intents the resolver admitted, and the rejected ones with their stable code, so the on-policy mask is reconstructible and equals the admitted set `reconcile` recomputes from the recorded resolution), the sampling `support` (policy id, revision and configuration hash), `logProb` (the recorded value, else the explicit literal `"unknown"`, never `0` or `null`), the `checkpoint` state hashes before and after (the first `before` is `"unknown"`: the episode records post-step hashes only), the observation digest, provenance (basis, task family, read-set, evidence refs) and one `actorId` per decision (the episode's only role, else `"unknown"` when several roles share it). The export also carries the verifier reference (always labelled `fixture` here), the attempt lineage and the control/treatment ids. `exportEpisodesForTraining` is the element-wise batch. `mode` follows the episode and `labelTrainingMode` keeps or lowers it (the digest follows) and refuses every upgrade, and any export whose own mode label is not an own key of the closed `fixture`/`replay`/`live` enum (`bogus`, `constructor`, an empty string), with `EPISODE_MODE_UPGRADE_FORBIDDEN`. `sanitizeValue` runs before the record is materialised; the export records the paths it removed in `sanitize.removed` and the ones the episode had already removed in `sanitize.inherited`. `digest` covers every other member, and `trainingBytes` is the canonical JSON plus one newline. The module exports and never trains: no learner, no network, no file write, no import outside the package. ## Comparative evaluation harness (mw.evaluation.fixture.v1)

`evaluate({ entries, scenario, partition, bootstrap })` compares coordination configurations on the hold-out seeds of a declared train/hold-out partition under one shared `{ steps, units }` budget and returns a fixture-labelled report of integer micro-unit metrics (1_000_000 is 1.0) per configuration and environment: validated completion with a seeded bootstrap interval, completion per compute unit spent, cost, p95 steps, all-success, all-fail and mixed groups, and the environment-specific secondary metrics. A configuration is a fixed rung-A policy set (`fixedBaseline`, `fixedChecked`, `fixedConfiguration`), a composition-selected set built from the exported `alternative` combinator and a declared selector (`composedConfiguration`, `seedParitySelector`), or an external set known only by configuration hash and policy `id@revision` (`externalConfiguration`); the harness neither trains nor evolves. Unequal budgets (`EVALUATION_BUDGET_UNEQUAL`), an overlapping partition (`EVALUATION_PARTITION_OVERLAP`, also for two seeds that start one `gateDraws` stream), a partition seed outside the uint32 domain or two seeds of one set that start one `gateDraws` stream (`EVALUATION_PARTITION_INVALID`), a bootstrap seed outside uint32 or the zero-state seed `0x9e3779b9` that would resample the stream of `0x9e3779b8` (`EVALUATION_BOOTSTRAP_INVALID`), an empty hold-out set (`EVALUATION_HOLDOUT_EMPTY`) and a malformed configuration hash (`EVALUATION_CONFIG_HASH_INVALID`) are refused. A comparison carries an `uplift` (or `deficit`) field only when two or more seeds back it and the interval excludes zero; otherwise `upliftWithheld` says `SINGLE_SEED` or `INTERVAL_CONTAINS_ZERO`. The continuity arm injects the artifact a failed attempt left in one episode into a later episode of a different seed (`laterSeed`) and records whether that successor consumed it, and the treatment-minus-control steps. `labelEvaluation` refuses any label but `fixture`, `evaluationBytes` gives the canonical bytes and `qa/integration/python-consumer/fixtures/evaluation-holdout-split.json` pins one report, re-hashed by `test_evaluation_fixture.py`. Fixture results never count as native PASS. `treeConfiguration(id, revision, tree)` (MechanicalWorkflows-s14.6, CA-R6) builds a composition configuration from a typed `CompositionTree`: any nesting, up to 16 levels, of `sequential`, `parallel`, `guarded` (declared guard), `alternative` (declared selector) and `inhibit` over fixed configurations at the leaves, with each combinator's counter memory collapsed to its maximum as `composedConfiguration` does; `repeated` is not a node because its run state is not a step counter (recorded amendment). The `configHash` is the digest of `{ id, revision, kind: "composition", tree }` where the canonical tree names leaves by configuration hash and guards and selectors by `id` and `revision` with sorted references, and the provenance records that tree (`combinator: "tree"`). An unknown operator, a missing child, a non-fixed leaf, a malformed guard or selector, an empty id or a tree nested deeper than the bound is refused with `CONFIG_TREE_INVALID`; a guarded, alternative or inhibit node whose declared `references` name a verifier decision (`verifier:`, `verdict:`, `receipt:`), a protected scope (`protected:`, `graph:protected:`, `authority:`) or the effects `effect:verify` and `effect:authorize` is refused with `CONFIG_TREE_PROTECTED_SCOPE`, so safety and verifier semantics stay fixed (every operator only proposes). `evaluate()` treats the result as kind `composition`; `qa/integration/python-consumer/fixtures/evaluation-composition-tree.json` pins one record and `test_evaluation_composition_tree.py` recomputes the leaf hashes, the arity and the tree hash in Python. Search over trees stays in the training repository.

### Mixed-mode episode evaluation (mw.evaluation.v1)

`evaluateEpisodes({ entries })` scores batches of `mw.episode.v1` episodes that each carry a mode label (`fixture`, `replay` or `live`). An entry has `kind: "episodes"`, the configuration `{ id, revision, configHash }`, a `pin` `{ agent, version, seed }`, one shared `{ steps, units }` budget and the labelled episodes. The report (`mw.evaluation.v1`, integer micro-units, `mixedEvaluationBytes` for the canonical bytes) carries per-mode blocks (`n`, within-budget share, mean steps, mean compute, p95 steps) computed only from episodes of that mode, plus per-episode refs, so a number never wears a label above its source: a label above the episode's own mode, or outside the closed enum, is refused with `EVALUATION_MODE_UPGRADE_FORBIDDEN`, while lowering a label is allowed. Replay and live blocks never certify: `certified` is the literal `false` on the report, every mode block and every comparison. Batches compare against the first entry only when their task families, mode sets, budget and agent/version/seed pin match, else `EVALUATION_BATCH_UNMATCHED` names the differing fields. Other refusals: `EVALUATION_PIN_INVALID`, `EVALUATION_EPISODES_EMPTY`, `EVALUATION_EPISODE_INVALID`, plus the existing `EVALUATION_NO_CONFIGURATIONS`, `EVALUATION_DUPLICATE_CONFIGURATION`, `EVALUATION_BUDGET_INVALID` and `EVALUATION_CONFIG_HASH_INVALID`. The harness trusts each episode's own `mode`; a live-labelled episode in the pinned test fixture `qa/integration/python-consumer/fixtures/evaluation-mixed-mode.json` is a test construct, and `test_evaluation_mixed_mode.py` re-hashes it and recomputes every block and comparison in Python.

## Exit report generator (mw.exit-report.v1)

`exportExitReport(inputs)` builds the 05 exit report template as one pure, canonical, digest-pinned record: commit, scenario ids and seeds, configured models and checkpoints, native environment revisions with their receipt ids, expected against observed evidence, the baseline and candidate comparisons with their confidence bounds (from an `EvaluationReport` whose digest must recompute), failed cases, profiler data in integer micro-units, residual risks, and the live-witness and authority-check availability. An absent value is the literal `"unknown"`. Mode labels are copied verbatim and the report mode is the lowest label present, so a fixture never rides into a live report; `labelExitReport` refuses any other label. The `milestone` is `incomplete` (with reasons) unless a live witness, an authority check, known evidence and a live mode are all present. Refusals: `EXIT_REPORT_COMMIT_INVALID`, `EXIT_REPORT_DUPLICATE_SCENARIO`, `EXIT_REPORT_NON_INTEGER`, `EXIT_REPORT_MODE_INVALID`, `EXIT_REPORT_MODE_UPGRADE_FORBIDDEN`, `EXIT_REPORT_EVALUATION_DIGEST_MISMATCH`. `qa/integration/python-consumer/fixtures/exit-report-fixture-only.json` pins one fixture-only record, re-hashed and re-derived by `test_exit_report_fixture.py`. A fixture-only record carries the commit `"unknown"` because no evidence was gathered at any commit, and the pinned fixture names that in its residual risks; only a replay or live record declares a 40 hex commit. Fixture results never count as native PASS. See `docs/10-current-state-and-gaps.md` for the field-to-source mapping.

## Sampled decision record (GPC-EAT-R007)

`sampleSupportedDecision({ seed, support, admitted, weights? })` is a seeded stochastic selector over a pre-sampling legal support S. The returned `SampledDecision` keeps `support` (S) and `admitted` (the resolver mask A, a subset of S) as two distinct fields, the `chosen` id, the sampler's original distribution `probabilities` and `behaviorLogProb` equal to log p_S(chosen). Without `weights` the sampler reports no probability and both values stay the literal `"unknown"`, never `0` or `null`. `validateSampledDecision` refuses a malformed record with `SIDECAR_SAMPLED_MALFORMED` and a log probability that differs from the original log p_S(chosen) (a value renormalized over A, a fabricated `0`, or a number with no recorded probabilities to check it against) with `SIDECAR_LOGPROB_NOT_ORIGINAL`. `sampledDecisionToSidecar` builds the `mw.coordination-decision.v1` sidecar from a validated sample with `support` = S. The deterministic two-way `Selector<O>` path records no probability and still exports `logProb` `"unknown"`. Fixture results never count as native PASS.
