# 01 — Workflow Contract Design and Validation

## Proposed data links
Under the proposed contract a workflow step would expose its typed input/output, effect scope, authority/version requirements, idempotency/retry behavior, verifier predicate and native evidence reference. No current MechanicalWorkflows step type exposes effect scope, authority/version or idempotency/retry fields; docs/11 D-01 adds a primitive only when a real consumer demonstrates it. A composition validates (a) type compatibility, (b) local postcondition establishing successor precondition, (c) independent permissions for each effect, validated by the host/native admission owner, not by MechanicalWorkflows, (d) checkpoint/retry semantics checked against the producer's native contract where one exists (Furnace 0.1.0 ships run resume / work retry but no effect-idempotency contract), and (e) an explicit bridge invariant/certificate (CAC 0.1 Bridge rule) from local validations to the overall intended claim; no bridge checker exists at HEAD.

Use \`CACWorkflowCompositionV0\` as a concept only. It can point to existing workflow step and source artifact IDs, but it must not create new authoritative IDs for Beads tasks, Forge operations/gates, Furnace attempts, Git revisions or HyperUnix answers (a non-exhaustive list).

## Exact examples to test
1. Agent creates a committed Git candidate, then invokes a native Forge full gate: the build receipt binds the gate definition (sha256) and source tree natively, the commit via envelope.gated_commit or the envelope-named run record, and the environment only as an unpinned descriptor (forge 0.2.1 rev 0deb972: execution_environment.pinned=false, env_mode=inherited). Caveat: the app-server gate.run path at rev 0deb972 returned gated_commit/gated_tree as null; commit binding is recovered by the rig's resolveCandidatePin over the run record (docs/13 Live witness), not frictionlessly by Forge.
2. A failed Forge predicate does not become a verified_candidate outcome or a Beads closed status merely because an agent message says the change was fixed.
3. Furnace-hosted retry after uncertain external effect must follow native reconciliation semantics (Furnace 0.1.0 ships reconciliation and retry verbs; idempotent Run establishment runs.ensure is absent at Furnace 513a688 and no effect-idempotency contract exists; Furnace reconciliation = run resume, work retry, run resume --continue; effect idempotency rests with the effect producer).
4. Reactive Fiber context for revision r1 cannot justify action on r2 without a version gate or an accepted staleness contract (none is defined anywhere in this repository; until one is, the version gate is the only admissible path).
5. A Beads claimed task may be no longer ready at execution; source-native task state is checked.
6. Two individual success receipts cannot prove arbitrary global integration correctness without an explicit bridge invariant/certificate (CAC 0.1 Theorem 3 with the Bridge premise; counterexample C3; Library docs/theory @ff9a8e1, hand-derived).
7. A learned workflow selection policy may improve speed (hypothesis: no learned policy, baseline, workload or measurement protocol exists at HEAD). Whatever its speed, it cannot bypass MW's reconcile protected-scope refusal (INTENT_SCOPE_PROTECTED) or the composition tree's protected-reference refusal (CONFIG_TREE_PROTECTED_SCOPE). An external native per-effect admission gate is unwitnessed; Furnace's documented admission is Run/Work resource admission.

## QA and acceptance
Create independent finite fixture state machines and negative controls; compare to current workflow libraries without silently changing their contracts. Run native Forge gates for any new code and retain exact source/evidence. Report PASS/FAIL/UNKNOWN for effect, evidence and observer obligations. Mapping from the shipped vocabularies is required: passed/failed/partial/unknown (VerificationResult.verdict), established/observed/unknown/not_run (ReceiptState) and Forge PASS/FAIL/partial-indeterminate; partial and not_run report as UNKNOWN with the raw value retained. Define observer obligation (no definition exists in the repo).
