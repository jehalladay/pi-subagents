# C003 — Stock headless semantics lose the subagent entirely

- **Claim:** C003 (source AGENTS-003, agents family) · **Axis/grade:** gap / ESTABLISHED
- **Pin:** ce180d82 (worktree `pin-ce180d82`), graded 2026-11-11

## Defect
Under stock headless semantics (`await session.prompt`, print, dispose) the default spawn mode loses the subagent. The Agent reply says "started in background… you will be notified", the parent turn ends, shutdown aborts the child before it has made one model call, and nothing reaches the parent. `@plan …` in the default `model` mention mode does nothing at all. README promises the opposite for mentions and warns only about scheduled jobs.

## Reproduction
```
cd probes/agents && ./RUN.sh p15-headless-background.probe.test.ts
# -> out/p15-headless-default-background.json, out/p15-headless-mention.json
```
Observed (pin harness `runPrintMode({hold:false})` followed by dispose; the harness's default `hold:true` is a host-side monkey-patch its header attributes to pi-chonky-step):
- Reply: `Agent started in background.… You will be notified when this agent completes.`
- At prompt return: `{childModelCalls:0, recordStatus:"running"}`; after dispose: `{recordStatus:"stopped", childFinishedItsTurn:false}`; `childOutputEverReachedParent:false`.
- Mention `@plan sketch the migration`: `modelCallsWhenPromptReturned:0, parentMessages:[], whatPiWouldPrint:"", modelCallsTotal:0, agentsEverSpawned:0`.

Sub-grade: that the `pi -p` binary has these semantics is SUPPORTED by node_modules/@earendil-works/pi-coding-agent/dist/modes/print-mode.js:105-108 (`await session.prompt`) and :138 (dispose); the binary was not run against a live model. Docs: README.md:195 claims `pi -p '@plan the migration'` "clones, spawns, and reports through the normal completion path"; README.md:110 warns only about scheduled subagents; docs/rpc.md:145 leaves waiting to "a headless host that wants to block on waitForAll()". Code: src/index.ts:1239-1268 (session_shutdown -> abortAll), :1175-1208 (model-mode mention returns `handled` without awaiting the clone); CHANGELOG.md:602 then :525 (a headless wait was added in 0.4.1 and later replaced by abortAll).

## Cost
Anyone running pi headlessly with shipped defaults (CI, cron, pipelines). The delegated work is dropped on every run and the printed answer is the parent's "I started an agent" text.

## Cure options
1. **Primary (investigator):** when `ctx.mode` is print/json, default `run_in_background` to false and say so in the reply — or hold the turn on `manager.waitForAll()`; await the mention clone when headless; correct README.md:195.
2. Alternative: keep background default but have session_shutdown drain running agents (bounded wait with a timeout) instead of abortAll when the host is headless.
3. Docs-only stopgap: README headless section stating that background spawns and mentions do not survive `pi -p`, with the `run_in_background:false` recipe.
