# C062 — workflowsEnabled:false does not switch off workflow_execute

- **Claim:** C062 (source EXECUTE-013, execute family) · **Axis/grade:** gap / ESTABLISHED
- **Pin:** ce180d82 (worktree `pin-ce180d82`), graded 2026-11-11

## Defect
`workflowsEnabled: false`, documented as "the master switch for scripted workflows" under which the model "cannot call it", does not switch off `workflow_execute`. In Workbench mode the tool stays registered; an embedded launch is refused with a bare `Workflows are disabled in this session.` (no pointer to the setting), and a detached launch simply runs.

## Reproduction
```
cd pin-ce180d82 && ./node_modules/.bin/vitest run --config ../probes/execute/vitest.probe.config.ts real-extension
# -> probes/execute/results/real-extension.json#E_workflowsDisabled
```
Settings `{workflowsEnabled:false, workbench:{workflowAgentBackend:'claude', capabilityGrants:[design,observe,execute,detach,claude:invoke]}}`:
- `registered` includes `workflow_execute` and `workflow_detached`, not `SubagentWorkflow`;
- embedded -> `{"error":{"code":"launch-failed","message":"Workflows are disabled in this session."}}`;
- detached -> `{"ok":true,"invoked":true,"status":"launched","hostMode":"detached"}` — **it runs**.

Promise: README.md:688. Code anchors: src/index.ts:2622 (only the embedded launcher checks `isWorkflowsEnabled`), :2665-2678 (detached launcher does not), :3484 (only SubagentWorkflow's registration is gated). Contrast the CLI flag's correct refusal (`results/cli-flag.json#V_cliFlag.disabled`, src/index.ts:3576-3582) which names the setting and the menu path.

## Cost
Operators who turn workflows off expecting no scripted orchestration: a model holding execute+detach+claude:invoke can still launch detached workflows; models hitting the embedded refusal get no remediation.

## Cure options
1. **Primary (investigator):** check `isWorkflowsEnabled()` once in the tool shell before either launcher (typed `workflows-disabled` code, message reusing the CLI flag's wording), or do not register `workflow_execute`/`workflow_detached` launch while the switch is off.
2. Alternative: keep registration but make the capability-grant admission require `workflowsEnabled` as a precondition for `workbench:execute`/`workbench:detach` to act.
