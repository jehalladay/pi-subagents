# C199 — The shipped install instruction installs different software

- **Claim:** C199 (source PACKAGING-001, packaging family) · **Axis/grade:** gap / ESTABLISHED
- **Pin:** ce180d82 (worktree `pin-ce180d82`), graded 2026-11-11

## Defect
The shipped install instruction cannot deliver this software: README.md:45 says `pi install npm:@tintinweb/pi-subagents`, but the npm registry serves upstream 0.23.2 (modified 2026-11-10, 200 files/2.8MB) while this tree is the fork jehalladay/Pi-subagents at version 0.20.0 whose entire Workbench sits under CHANGELOG `[Unreleased]`. No published artifact contains the features the same README/docs describe.

## Reproduction
```
npm view @tintinweb/pi-subagents version time.modified dist.fileCount --json
# -> {"version":"0.23.2","time.modified":"2026-11-10T10:56:21.150Z","dist.fileCount":200}
#    (probes/packaging/npm-view-published.json)
```
Local facts: package.json `version=0.20.0`; CHANGELOG.md:8 `## [Unreleased]` (Workbench entry) vs :17 `## [0.20.0] - 2026-10-09`; `git remote -v` -> origin https://github.com/jehalladay/Pi-subagents; docs/workbench/17-packaging-and-operations.md:5 "Fork remains jehalladay/pi-subagents".

## Cost
Every consumer or agent who reads this tree's README and runs the install line gets different software with none of the documented workbench surface; silent feature absence on first contact.

## Cure options
1. **Primary (investigator):** add a fork install note: `pi install git:github.com/jehalladay/Pi-subagents` (pi install supports git: sources, verified via `pi install --help`) or a packed-tarball path, until the fork publishes under its own name.
2. Publish the fork under its own (scoped) name and update README; C210 (PACKAGING-012) notes the version-collision hazard of publishing at the current name/0.20.0.
3. Add a README banner distinguishing fork features from the published upstream package so docs readers know which surface they hold.
