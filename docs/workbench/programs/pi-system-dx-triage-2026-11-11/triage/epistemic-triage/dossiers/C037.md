# C037 — A successful detached run with a large result is reported as failed

- **Claim:** C037 (source DETACHED-005, detached family) · **Axis/grade:** UX / ESTABLISHED
- **Pin:** ce180d82 (worktree `pin-ce180d82`), graded 2026-11-11

## Defect
A detached workflow that COMPLETES with a value larger than the 256 KiB snapshot bound is reported `terminal:'failed'` with no result: the terminal classifier overwrites the true completed status when `safeJson` refuses the oversized value, so a successful run (whose native effects all happened) presents as a failure.

## Reproduction
Probe P5 (probes/detached): script `return "x".repeat(300*1024)` ->
```
snapshot { terminal:'failed',
           diagnostic:'Workflow returned a result exceeding the bounded JSON snapshot contract.',
           resultPresent:false }
```
Code anchor: src/workbench/hosts/local-detached.ts:741-743 — terminal set to `'completed'` then reassigned `'failed'` in the `safeJson` catch.

## Cost
Agents and operators mis-triage successful runs as failures and may re-run or reconcile work that already succeeded; any workflow returning large payloads hits it every time.

## Cure options
1. **Primary (investigator):** keep `terminal:'completed'` and add `resultOmitted:'exceeds-snapshot-bound'` (result stays absent) instead of reclassifying the run as failed.
2. Alternative: spill the oversized result to a file beside the receipt (`<id>/result.json`) and carry a reference in the snapshot, keeping the 256 KiB bound on the wire only.
3. Minimum: keep the current shape but make the diagnostic state explicitly that the run completed and only the result was dropped.

## Related
C051 (EXECUTE-002, 4000-char completion truncation) and C015 (AGENTS-015, 500-char background preview) are the embedded-side result-loss bounds; this is the detached-side variant with the extra harm of a false verdict.
