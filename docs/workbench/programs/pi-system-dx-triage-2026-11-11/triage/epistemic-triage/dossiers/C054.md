# C054 — Nothing model-facing can stop a launched workflow

- **Claim:** C054 (source EXECUTE-005, execute family; SAME_ORIGIN OBSERVE-015) · **Axis/grade:** missing-req / ESTABLISHED
- **Pin:** ce180d82 (worktree `pin-ce180d82`), graded 2026-11-11

## Defect
No model-facing tool can stop a run that `workflow_execute` (or `SubagentWorkflow`) launched. Embedded: `workflow_control` over the returned `{provider:'pi-workflow',type:'task'}` reference refuses cancel/stop/interrupt/kill as unknown-action and `steer_subagent` does not know the id, so a runaway script runs to its natural end. Detached: `workflow_control` refuses cross-scope because nothing ingests detached readings into the session projection, the launcher grants the host only inspect+execute, and the host process stays resident after the script is done.

## Reproduction
```
cd pin-ce180d82 && ./node_modules/.bin/vitest run --config ../probes/execute/vitest.probe.config.ts execute-extra
# -> probes/execute/results/execute-extra.json#M_noModelStop
```
Observed: `observeWhileRunningStatus 'running'`; control cancel|stop|interrupt|kill each -> `{"status":"refused","policy":"unknown-action","reason":"The action is not an allowed native verb for this provider."}`; `steer_subagent` -> `Agent not found: "wf_364d1ca6ff17"`; `finalStatus 'completed'` only after `waitedMsForNaturalEnd 9245`. Detached (`results/real-extension.json#F_detachedGolden`): controlCancel/controlShutdown -> `policy:"cross-scope"`, receipt permissions `['inspect','execute']`. Linger (`results/execute-misc.json#T_detachedLinger`): `aliveThreeSecondsAfterTerminal true, rssKb 205988, threads 7, launchReplyNamesPid false`.

Code anchors: src/workbench/control.ts:30-37 `NATIVE_CONTROL_ACTIONS` has no pi-workflow provider; only abort sites are src/ui/workflow-menu.ts:275 and session_shutdown (src/index.ts:1254); src/index.ts:2672 `permissions: ["inspect","execute"]`; src/workbench/hosts/local-detached.ts:777 (host permission check), :461 (retentionMs default 600000, timeoutMs default 86400000); src/workbench/detached-observer.ts has 0 importers in src; test/workbench-detached-control-live.test.ts:13-14 declares the booted reading UNREALISED citing wb-79k.3 (HELD).

## Cost
Any agent that mis-launches or wants to abandon a workflow: only a human in /agents -> Workflows (embedded) or a manual SIGTERM (detached) can stop it. Each detached launch keeps a ~200 MB node process for the 10-minute retention window (up to 24 h for a hung script).

## Cure options
1. **Primary (investigator):** add `pi-workflow: ['cancel']` to `NATIVE_CONTROL_ACTIONS` with an executor that calls `task.abortController.abort()`; launch detached hosts with cancel+shutdown permissions and apply the launch receipt through `applyDetachedReading` so `workflow_control` admits them (closes wb-79k.3).
2. Alternative: retire the resident detached host at terminal instead of holding the full retention window, and print the host pid in the launch reply as a documented manual-stop path until control is wired.
3. Related mechanism (SAME_ORIGIN OBSERVE-015): the furnace control leg needs the ownership edge (`relate`) applied at observe time — same ingestion-gap family, see C076 (FURNACE-001).
