## Rival readings tested
- Strongest case as worded: Three code facts (throwing git helper, detached worktree, force-remove in catch) entail the loss mechanically.
- Strongest counter-reading: 'Recoverable' presumes the edits mattered; a reviewer could say the agent's work was never committed to a branch so nothing 'owned' was lost. The code still destroys bytes the agent wrote.
- Narrower supported proposition: If any git step in cleanupWorktree fails after the agent edited files, the edits (and any fresh commit's reference) are removed with the worktree and the caller is told there were no changes.
- Rivals preserved: the branch-failure case leaves a dangling commit object recoverable by fsck until gc - 'discard' is strictly true of the reference and of the working tree, not of the object store

- Independence: Nov-4 program, SKILL and README restate the same reading (one lineage); the code is the witness.
